# Codex 1M Context

[English](README.md) · [简体中文](README.zh-CN.md) · [हिन्दी](README.hi.md) · [Русский](README.ru.md)

Настройка контекста **1 000 000 токенов в локальном клиенте Codex** для каждой записи в его кешированном каталоге моделей. Один офлайн-скрипт Python, без зависимостей, сетевых запросов и вызовов API. Не читает `auth.json` и не отправляет файлы наружу.

**Индикатор 1M не гарантирует, что сервер примет 1M входных токенов.** Инструмент меняет метаданные клиента, а не возможности модели, тариф или квоты. Провайдер может отклонить запрос, превышающий фактический лимит. Вход, инструкции, данные инструментов, ответ и рассуждения занимают общее окно контекста: весь миллион не всегда доступен для вашего ввода.

## Начало работы

1. При необходимости установите **Python 3.11 или новее**; скрипт не устанавливает Python. Версия Codex должна поддерживать `model_catalog_json`.
2. Один раз откройте установленный Codex, чтобы он создал `models_cache.json` в домашнем каталоге Codex, затем закройте его перед изменением настроек.
3. На https://github.com/IveSan83/codex-1m-context выберите **Code → Download ZIP**, распакуйте архив и откройте терминал в распакованной папке. Альтернатива через Git:

```sh
git clone https://github.com/IveSan83/codex-1m-context.git
cd codex-1m-context
```

4. Выполните команду для своей системы. На Windows также можно дважды щёлкнуть `START.cmd` для применения настроек; Python 3.11+ всё равно необходим.

| Действие | Windows | macOS / Linux |
| --- | --- | --- |
| Применить | `py -3 enable_1m.py` | `python3 enable_1m.py` |
| Предпросмотр без записи | `py -3 enable_1m.py --dry-run` | `python3 enable_1m.py --dry-run` |
| Восстановить последнюю копию | `py -3 enable_1m.py --restore latest` | `python3 enable_1m.py --restore latest` |

5. Перезапустите Codex. В палитре команд VS Code выполните **Developer: Reload Window**, затем откройте новый диалог Codex. Проверьте индикатор и поведение самостоятельно.

По умолчанию используется каталог из `CODEX_HOME`, если переменная задана, иначе `~/.codex`. Добавьте `--home "path/to/codex-home"` к любой команде для выбора другого каталога; при восстановлении укажите тот же каталог.

## Что меняется

Скрипт читает локальный `models_cache.json`, создаёт свой JSON-каталог в домашнем каталоге Codex и задаёт каждой записи контекст и максимальный контекст **1 000 000**, эффективный контекст **100%** и порог автоматического сжатия **900 000 токенов**. Остальные метаданные моделей сохраняются. При достижении порога Codex может сжать историю диалога, чтобы освободить место; это не гарантирует, что сервер примет 900 000 токенов.

В `config.toml` изменяются только три ключа верхнего уровня:

- `model_catalog_json`: созданный локальный каталог.
- `model_context_window = 1000000`
- `model_auto_compact_token_limit = 900000`

Остальные настройки, включая MCP, сохраняются. Созданные каталоги и резервные копии находятся в `<Codex home>/codex-1m-context/`. Перед изменениями создаются копии, файлы записываются атомарно; повторное применение тех же настроек не создаёт лишних изменений. Восстановление меняет только эти три ключа и сохраняет последующие правки остальных настроек. При конфликте значений этих ключей или изменении файлов каталога и копии оно отказывает. Храните копии приватно: исходная конфигурация может содержать токены доступа или другие секреты.

## Обновления и устранение проблем

Созданный каталог — **снимок**: Codex использует его вместо автоматического обновления списка моделей. После обновления Codex, изменения доступности моделей или смены аккаунта сначала восстановите исходные настройки, откройте Codex для обновления обычного кеша, закройте его и запустите скрипт снова.
Восстановление возвращает прежние значения. Если они уже указывали другой пользовательский каталог, сначала отключите прежнее переопределение, чтобы обычный кеш мог обновиться.

Если `models_cache.json` отсутствует, один раз откройте Codex обычным способом и убедитесь, что скрипт выбирает тот же домашний каталог. Профиль или настройки с более высоким приоритетом могут переопределить корневые значения; инструмент не переписывает такие переопределения. При ошибке лимита контекста на сервере восстановите исходные настройки и используйте лимит, поддерживаемый провайдером.
