# Codex 1M Context

[English](README.md) · [简体中文](README.zh-CN.md) · [हिन्दी](README.hi.md) · [Русский](README.ru.md)

स्थानीय कैश में मौजूद मॉडल सूची की हर प्रविष्टि के लिए **Codex क्लाइंट का संदर्भ 1,000,000 टोकन** पर सेट करें। एक ऑफलाइन Python स्क्रिप्ट; कोई अतिरिक्त निर्भरता या नेटवर्क/API कॉल नहीं। यह `auth.json` नहीं पढ़ती और फ़ाइलें अपलोड नहीं करती।

**1M दिखने का मतलब यह नहीं कि सर्वर 1M इनपुट टोकन स्वीकार करेगा।** यह टूल क्लाइंट का मेटाडेटा बदलता है; मॉडल की क्षमता, आपका प्लान या उपयोग कोटा नहीं बदलता। वास्तविक सीमा से बड़ा अनुरोध प्रदाता अस्वीकार कर सकता है। इनपुट, निर्देश, टूल डेटा, आउटपुट और रीजनिंग एक ही संदर्भ विंडो में जगह लेते हैं; पूरे 1M टोकन हमेशा आपके इनपुट के लिए उपलब्ध नहीं होते।

## शुरू करें

1. आवश्यकता हो तो पहले **Python 3.11 या नया संस्करण** इंस्टॉल करें; स्क्रिप्ट Python इंस्टॉल नहीं करती। Codex का संस्करण `model_catalog_json` का समर्थन करना चाहिए।
2. इंस्टॉल किए गए Codex को एक बार खोलें ताकि उसके होम फ़ोल्डर में `models_cache.json` बन जाए। फिर सेटिंग बदलने से पहले Codex बंद करें।
3. https://github.com/IveSan83/codex-1m-context पर **Code → Download ZIP** चुनें, ZIP निकालें और निकाले गए फ़ोल्डर में टर्मिनल खोलें। Git का विकल्प:

```sh
git clone https://github.com/IveSan83/codex-1m-context.git
cd codex-1m-context
```

4. अपने सिस्टम के लिए कमांड चलाएँ। Windows पर सेटिंग लागू करने के लिए `START.cmd` पर डबल-क्लिक भी कर सकते हैं; Python 3.11+ फिर भी आवश्यक है।

| काम | Windows | macOS / Linux |
| --- | --- | --- |
| सेटिंग लागू करें | `py -3 enable_1m.py` | `python3 enable_1m.py` |
| बिना फ़ाइल बदले पूर्वावलोकन | `py -3 enable_1m.py --dry-run` | `python3 enable_1m.py --dry-run` |
| नवीनतम बैकअप से बहाल करें | `py -3 enable_1m.py --restore latest` | `python3 enable_1m.py --restore latest` |

5. Codex फिर से शुरू करें। VS Code के Command Palette में **Developer: Reload Window** चलाएँ, फिर नई Codex बातचीत खोलें। संकेतक और व्यवहार की जाँच स्वयं करें।

डिफ़ॉल्ट होम, सेट होने पर `CODEX_HOME` है; अन्यथा `~/.codex`। दूसरा होम चुनने के लिए किसी भी कमांड में `--home "path/to/codex-home"` जोड़ें; बहाल करते समय भी वही होम इस्तेमाल करें।

## क्या बदलता है

स्क्रिप्ट स्थानीय `models_cache.json` पढ़कर Codex होम में अपनी JSON मॉडल सूची बनाती है। हर प्रविष्टि का संदर्भ और अधिकतम संदर्भ **1,000,000**, प्रभावी संदर्भ **100%**, और बातचीत के इतिहास को स्वतः संक्षिप्त करने की सीमा **900,000 टोकन** पर सेट होती है। बाकी मॉडल मेटाडेटा सुरक्षित रहता है। सीमा पर Codex जगह बनाने के लिए इतिहास संक्षिप्त कर सकता है; इससे सर्वर के 900,000 टोकन स्वीकार करने की गारंटी नहीं मिलती।

`config.toml` में केवल ये तीन शीर्ष स्तर के कुंजी मान बदलते हैं:

- `model_catalog_json`: बनाई गई स्थानीय मॉडल सूची।
- `model_context_window = 1000000`
- `model_auto_compact_token_limit = 900000`

MCP सहित बाकी कॉन्फ़िगरेशन सुरक्षित रहता है। बनाई गई मॉडल सूची और बैकअप `<Codex home>/codex-1m-context/` में रहते हैं। बदलाव से पहले बैकअप बनता है और फ़ाइलें एटॉमिक तरीके से लिखी जाती हैं; वही सेटिंग फिर लागू करने से अनावश्यक नए बदलाव नहीं होते। बहाली केवल इन तीन कुंजी मानों को वापस करती है और दूसरी सेटिंग के बाद के संपादन सुरक्षित रखती है। इन कुंजी मानों में टकराव होने या बनाई गई सूची/बैकअप बदलने पर बहाली रुक जाती है। बैकअप निजी रखें: मूल कॉन्फ़िगरेशन में एक्सेस टोकन या दूसरे गोपनीय मान हो सकते हैं।

## अपडेट और समस्या समाधान

बनाई गई सूची एक **स्नैपशॉट** है: Codex सामान्य मॉडल सूची को स्वतः रीफ़्रेश करने के बजाय इसी का उपयोग करता है। Codex अपडेट होने, उपलब्ध मॉडल बदलने या खाता बदलने पर पहले मूल सेटिंग बहाल करें। फिर सामान्य कैश रीफ़्रेश करने के लिए Codex खोलें, उसे बंद करें और स्क्रिप्ट दोबारा चलाएँ।
बहाली पुराने मान वापस लाती है। यदि उनमें पहले से कोई दूसरी कस्टम मॉडल सूची चुनी गई थी, तो सामान्य कैश रीफ़्रेश होने के लिए पहले उस पुराने ओवरराइड को बंद करें।

`models_cache.json` न मिले तो Codex सामान्य रूप से एक बार खोलें और सुनिश्चित करें कि स्क्रिप्ट वही होम चुन रही है। प्रोफ़ाइल या अधिक प्राथमिकता वाली सेटिंग शीर्ष स्तर के मानों को बदल सकती है; यह टूल उन ओवरराइड को नहीं बदलता। सर्वर संदर्भ सीमा की त्रुटि दे तो मूल सेटिंग बहाल करें और प्रदाता की समर्थित सीमा इस्तेमाल करें।
